<objective>
Make the archive top bar mobile-friendly: hide the radio-button view selector on small screens and let users toggle between slideshow and table views by tapping anywhere on the top bar.

Purpose: On mobile the view selector radio buttons are cramped and waste space. A tap-anywhere interaction is more natural for touch devices and keeps the bar uncluttered.
Output: WorkTopBar.svelte with CSS hiding and tap handler; WorkLayout.svelte with toggleViewMode() wired up.
</objective>

  <name>Task 1: Hide view selector on mobile in WorkTopBar</name>
  <files>packages/sveltekit/src/lib/components/Works/WorkTopBar.svelte</files>
  <action>
In `WorkTopBar.svelte`, inside the existing `@media (max-width: 800px)` block within `.top-bar`, add a rule to hide the `.view-selection-outer` div:

```scss
.view-selection-outer {
    display: none;
}
```

This hides the radio-button fieldset on mobile while leaving it fully functional on desktop. The `.back` link is already hidden at this breakpoint — `.view-selection-outer` should follow the same pattern.

Also add the `onToggleViewMode` prop and wire `onclick` on the `.top-bar` `<header>` element:

1. Update props in `<script lang="ts">` to add `onToggleViewMode: () => void` to the props destructure:
   ```ts
   const { title, yearDisplay, hasMedia, viewMode, onSetViewMode, onToggleViewMode } = $props<{
       title: string;
       yearDisplay: string;
       hasMedia: boolean;
       viewMode: ViewMode;
       onSetViewMode: (mode: ViewMode) => void;
       onToggleViewMode: () => void;
   }>();
   ```

2. Add `onclick` to the `<header class="top-bar">` element:
   ```svelte
   <header class="top-bar" onclick={onToggleViewMode}>
   ```

   Note: On desktop, clicking a radio `<input>` inside the header will fire both the input's `onchange` AND the header's `onclick`. To prevent the header tap-toggle from double-firing on desktop radio clicks, stop propagation from within the `.view-selection-outer` div:
   ```svelte
   <div class="view-selection-outer" onclick={(e) => e.stopPropagation()}>
   ```
   This means desktop radio clicks set the view via `onSetViewMode` only; mobile taps on the bare header toggle via `onToggleViewMode` only.

   Also apply `cursor: pointer` to `.top-bar` in the mobile media query so the tap target is obvious:
   ```scss
   @media (max-width: 800px) {
       cursor: pointer;
       ...existing rules...
   }
   ```
