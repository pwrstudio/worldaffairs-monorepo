  <action>
Edit WorkDetail.svelte to use the `defaultView` field from the work document to set the initial view mode:

1. **Add a mapping function** before the existing `$state` declarations in the `<script>` block. Place it after the props destructuring and before the state variables:

```typescript
function defaultViewToMode(dv: Work['defaultView']): ViewMode {
    if (dv === 'text') return 'text';
    if (dv === 'grid') return 'grid';
    return 'slideshow'; // 'image' and undefined both map to slideshow
}
```

This maps Sanity's `'image' | 'text' | 'grid'` to the component's `'slideshow' | 'text' | 'grid'` ViewMode type. The `'image'` -> `'slideshow'` mapping is necessary because Sanity uses "image" while the component uses "slideshow" (the Swiper-based view).

2. **Replace the hardcoded viewMode initialiser.** Find:
```typescript
let viewMode = $state<ViewMode>('slideshow');
```

Replace with:
```typescript
// svelte-ignore state_referenced_locally
let viewMode = $state<ViewMode>(defaultViewToMode(work.defaultView));
```

The `svelte-ignore state_referenced_locally` comment follows the existing pattern already used in this component for `media` and `yearDisplay` (where `$state` is initialised from a prop value).

The GROQ query does NOT need changes -- the `...` spread in `workBySlug` already projects all scalar fields including `defaultView`. The `Work` type from `@sanity-types` already exposes `defaultView?: 'image' | 'text' | 'grid'`.

IMPORTANT: Do NOT use `$derived` for viewMode -- it must remain `$state` because the user can change the view mode interactively.
