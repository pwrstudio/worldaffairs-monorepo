## Directory Purposes

**packages/sveltekit/src/lib/components/:**

- Purpose: All user-facing UI components
- Contains: Svelte component files organized by feature domain
- Key subdirectories:
    - `Tables/`: Generic and specific table components (DataTable, MusicTable, VideoTable, TourDateTable, WorksTable)
    - `Works/`: Work detail interface and media display (WorkDetail, MediaSlideshow, slides/)
    - `Ticker/`: Scrolling commodity ticker component
    - `Clock/`: Clock displays by timezone
    - `Header/`, `Footer/`, `Contact/`, `NewsLetter/`, `Store/`: Home page sections
    - `slides/`: Media slide types (ImageSlide, AudioSlide, VideoSlide)

**packages/sveltekit/src/lib/modules/:**

- Purpose: Business logic, data access, and state management
- Contains:
    - `sanity/`: Sanity client config, data fetching, text rendering
    - `stores/`: Svelte stores (currently minimal/empty)
    - `utils/`: Helper functions (URL validation, data transformation, etc.)

**packages/sveltekit/src/lib/types/:**

- Purpose: TypeScript type definitions for app-specific data structures
- Contains: ClockLocation, Commodity, Column, LinkListItem types
- Note: Primary data types come from Sanity-generated types via `@sanity-types` alias

**packages/sveltekit/src/lib/enums/:**

- Purpose: Enum values for component configuration
- Contains: TableType enum with values (New, Music, Video, TourDates, Products, Works)

**packages/sveltekit/src/lib/groq/:**

- Purpose: GROQ query definitions for Sanity CMS
- Contains: Combined query for all home page data, single work query with nested media

**packages/sveltekit/src/lib/constants/:**

- Purpose: Configuration constants
- Contains: SANITY_ID project identifier

**packages/sveltekit/src/routes/:**

- Purpose: Page routing and server-side data loading
- Contains:
    - `+page.svelte`, `+page.ts`: Home page component and loader
    - `+layout.svelte`: Root layout with Swiper CSS import
    - `works/[slug]/+page.svelte`, `works/[slug]/+page.ts`: Work detail page

**packages/sanity/:**

- Purpose: Headless CMS configuration and schema
- Contains: Sanity schema definitions, generated TypeScript types
- Key file: `sanity.types.ts` (generated by Sanity, imported via alias)

**packages/scripts/import-to-sanity/:**

- Purpose: Data import utility scripts
- Contains: Node.js scripts for importing tour dates and other data to Sanity

## Key File Locations

**Testing:**

- No test files present in codebase

## Naming Conventions

**Files:**

- Components: PascalCase (e.g., `WorkDetail.svelte`, `DataTable.svelte`)
- Utilities: camelCase (e.g., `commodities.svelte.ts`)
- Configuration: lowercase with dots (e.g., `svelte.config.js`)
- Index files: Use `index.ts` for barrel exports

**Directories:**

- Feature directories: PascalCase (e.g., `Works/`, `Tables/`, `Clock/`)
- Utility directories: lowercase (e.g., `modules/`, `types/`, `constants/`)
- Route directories: lowercase or bracketed params (e.g., `routes/`, `works/[slug]/`)

**Types:**

- Type names: PascalCase (e.g., `ClockLocation`, `Column`, `MediaItem`)
- Enum names: PascalCase (e.g., `TableType`)
- Constants: UPPER_SNAKE_CASE (e.g., `SANITY_ID`)

## Where to Add New Code

**New Feature:**

- Primary code: `packages/sveltekit/src/lib/components/[FeatureName]/`
- Related data types: `packages/sveltekit/src/lib/types/index.ts`
- Related queries: `packages/sveltekit/src/lib/groq/index.ts`

**New Component/Module:**

- UI component: `packages/sveltekit/src/lib/components/[ComponentName].svelte`
- Utility module: `packages/sveltekit/src/lib/modules/[moduleName]/index.ts`
- Store: `packages/sveltekit/src/lib/modules/stores/index.ts`

**New Page/Route:**

- Page component: `packages/sveltekit/src/routes/[page]/+page.svelte`
- Data loader: `packages/sveltekit/src/routes/[page]/+page.ts`
- Dynamic route: `packages/sveltekit/src/routes/[param]/+page.svelte` (use brackets for dynamic segments)

**Utilities:**

- Shared helpers: `packages/sveltekit/src/lib/modules/utils/index.ts`
- Constants: `packages/sveltekit/src/lib/constants/index.ts`

## Special Directories

**packages/sveltekit/static/:**

- Purpose: Static assets served at root
- Generated: No
- Committed: Yes
- Contains: Images (fire.gif), potentially other static files

**packages/sveltekit/.svelte-kit/:**

- Purpose: SvelteKit build output and generated types
- Generated: Yes (auto-generated by `svelte-kit sync`)
- Committed: No (in .gitignore)

**packages/sanity/.sanity/:**

- Purpose: Sanity CLI configuration and cache
- Generated: Yes
- Committed: No

**node_modules/:**

- Purpose: Dependencies
- Generated: Yes (via pnpm)
- Committed: No (in .gitignore)

## Import Paths & Aliases

**Path Aliases:**

- `$lib/`: Maps to `packages/sveltekit/src/lib/`
- `@sanity-types`: Maps to `packages/sanity/sanity.types.ts`

**Import Patterns:**

```typescript
// Component imports
import DataTable from '$lib/components/Tables/DataTable.svelte';

// Type imports
import type { Work } from '@sanity-types';
import type { Column } from '$lib/types';

// Utility imports
import { loadData } from '$lib/modules/sanity';
import { queries } from '$lib/groq';
import { isUrl } from '$lib/modules/utils';

// Constant imports
import { SANITY_ID } from '$lib/constants';

// Enum imports
import { TableType } from '$lib/enums';
```

## File Structure Summary

**Component Hierarchy (by feature):**

- Home page orchestrates all sections via data loading
- Table components (generic DataTable + specific implementations)
- Work detail view (WorkDetail → MediaSlideshow → media slides)
- Stateless section components (Header, Footer, Contact, etc.)
- Utility components (Ticker, Clock)

**Data Flow Files:**

1. Route loader (`+page.ts`) → calls
2. Data access module (`modules/sanity/index.ts`) → calls
3. Query definitions (`lib/groq/index.ts`)
